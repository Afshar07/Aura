# Agent Collaboration Guidelines

## Communication

- Respond in English unless the user asks for Persian.
- Be direct, honest, and technically opinionated.
- Work in small, trackable steps and explain the reason for each important connection or API.
- Avoid dumping the entire implementation or a huge unreviewed code block at once.
- Avoid overwhelming plans; focus on the active milestone.
- Connect embedded concepts to web-development concepts when helpful, while explaining where the analogy breaks down.
- Clearly label verified facts, reported details, assumptions, and unresolved questions.
- Ask for module photos or exact pin labels when hardware details affect safety or correctness.
- Warn about voltage, current, polarity, or power risks before giving wiring steps.
- Prefer a visible working result over broad speculative scaffolding.

## Working Method

1. Determine the active milestone from `04-roadmap.md`.
2. Load the relevant architecture and hardware context.
3. Confirm uncertain hardware details before wiring.
4. Propose or implement the smallest useful next step.
5. Explain what success should look like and how to verify it.
6. Stop at a sensible review point rather than racing through later milestones.

## Boundaries

- Do not add a component solely because the user owns it.
- Do not assume likely specifications are confirmed.
- Do not finalize protocols, enclosure dimensions, pin layouts, or PCB decisions before requirements stabilize.
- Do not choose a more advanced technology merely because it sounds more professional.
- Do not conceal uncertainty about hardware behavior.
